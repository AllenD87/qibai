## 2. 技术栈

- **应用壳**：Tauri v2（Rust），单二进制，前端资源 gzip 压缩后嵌入（默认 compression feature）。
- **前端**：原生 HTML/CSS/JavaScript，无前端框架、无构建步骤（`frontendDist: "../src"` 直接嵌入）。
- **核心逻辑**：Rust（qibai-core），负责 LLM、技能、语音、设置、存储等。
- **平台**：Linux X11（真机 webkit2gtk-4.1 2.50.4 + compiz 合成器）/ Windows / macOS 三平台目标。

## 3. 核心运行机制

### 3.1 IPC 双通道（tauri-bridge.js）

前端与后端通信统一走 `tauri-bridge.js`，它同时挂 `window.QibaiBridge` 和全局裸 `invoke`/`listen`：

- **invoke(cmd, args)**：Tauri 下走 `__TAURI__.invoke` 或 `__TAURI_INTERNALS__.invoke`；浏览器下走 localStorage mock。
- **listen(event, handler)**：Tauri 下优先 `__TAURI__.event.listen`；**因 `withGlobalTauri:false`，`__TAURI__` 不存在，实际走 `__TAURI_INTERNALS__.invoke('plugin:event|listen', {event, handler})`**，handler 经 normalized 包装（兼容"完整事件对象"与"裸 payload"两种回调形态）。

后端 106 个 `#[tauri::command]` 自定义命令（get_settings/save_settings/send_message/ctx_menu_pick 等）经 invoke 调用。

### 3.2 事件系统（emit → listen）

后端通过 `WebviewWindow::emit` / `AppHandle::emit` 广播事件，前端 listen 接收。实测后端 emit 12 种事件、前端 listen 30 种事件，例如：

| 事件 | 方向 | 用途 |
|---|---|---|
| `qibai://ctx-action` | 后端→主窗 | 右键菜单动作（lock/guard/console/minimal/transbg/exit） |
| `qibai://pet-say` | 后端→主窗 | 桌宠说话气泡 |
| `qibai://tts-speak` | 后端→主窗 | TTS 朗读触发 |
| `qibai://pet-perform` | 后端→主窗 | 动作演出 |
| `qibai://ui-nav` / `ui-minimal` | 后端→各窗 | 界面导航/最小化 |
| `qibai://reminder` | 后端→主窗 | 久坐/喝水/护眼提醒 |

**事件监听是应用的核心神经**：菜单动作、说话、语音、动作、界面切换、提醒全部依赖它。

### 3.3 右键菜单链路（透明背景触发路径）

```
用户右键主窗
  → main.rs 创建/定位 ctx-menu 窗（menu.html）
  → 用户点击「透明背景」→ menu.html pick('transbg')
  → invoke('ctx_menu_pick', {action:'transbg'})
  → main.rs ctx_menu_pick：关闭菜单窗 + 向非菜单窗 emit("qibai://ctx-action",{action:'transbg'})
  → pet.js listen('qibai://ctx-action') 回调：解析 action==='transbg'
  → state.transparentBg 取反 → repaintFrame() 重绘 → save_settings 持久化
```

### 3.4 透明背景渲染链（repaintFrame）

主窗 canvas 整帧重绘顺序：
1. `ensureCanvas` 初始化画布
2. `clearRect` 清空整帧
3. **仅当 `state.transparentBg === false`** 才填充 `#FFFDFB→#F7F3FA` 渐变物理底色（v30 为根治无合成器 X11 拖动残影引入，不可直接删除）
4. `drawImage` 绘制角色 RGBA PNG 帧

透明 = 跳过第 3 步物理底色 + `html,body{background:transparent}`（v35 加的 CSS）+ 主窗 `transparent(true)` 创建。三者齐备才有像素级透明。

## 5. ★ 权限模型（Tauri v2 ACL / capabilities）—— 本次全局根因

**Tauri v2 用 capabilities 声明前端可通过 IPC 调用哪些内置/插件命令。** 后端 Rust 直调插件 API 不受 capabilities 限制；只有前端 IPC 调用受限。

### 根因

项目此前**没有 `src-tauri/capabilities/` 目录**。Tauri v2 在无 capabilities 文件时**不自动应用 `core:default`**，导致前端 `plugin:event|listen` 被 ACL 拒绝（真机日志实证：`Command plugin:event|listen not allowed by ACL`）。

### 影响面（远超透明背景）

前端 30 种事件 listen 全部走 `plugin:event|listen`，全部被 ACL 拦截 → **说话、语音、动作、界面切换、提醒、菜单动作等事件驱动功能大面积静默失效**。透明背景点不动只是其中之一。

### 修复

新增 `capabilities/default.json`：
- `core:default`：聚合所有 core 插件默认权限（build.rs 证实其含 `event:default`/`window:default`/`webview:default` 等）
- `core:event:default`：显式双保险，含 `allow-listen`/`allow-unlisten`/`allow-emit`/`allow-emit-to`
- `autostart:default`、`notification:default`：项目已集成的插件（防御性授权）

`windows: ["*"]` 覆盖全部窗口。

### 经验

- Tauri v2 项目**必须**显式维护 capabilities，不能依赖默认。
- 前端功能"静默失效且无报错"时，优先在 listen 注册处埋 `.catch` 日志——ACL 拦截不会抛到前端业务层，只会在 listen Promise 拒绝时暴露。
- 自定义 `#[tauri::command]` 命令不受 capabilities 限制，只有内置/插件命令（`plugin:xxx|yyy`）受限。
